# Delivery

## Branches

- `main` is the only durable branch. Protected: PR required, CI green, no
  direct pushes, no force-push.
- Every task gets a short-lived feature branch off `main`.
- Branch name = task name, format `<area>-<short-description>`.
  Areas: `framework-`, `worker-`, `plugin-water-`, `plugin-hello-`,
  `frontend-`, `docs-`.
- PR title: `type(scope): summary` — no ID. Reference the task by its name in
  the PR description, e.g. "Task: framework-problem-protocol".
- Delete the branch after merge.

## PRs

- One task per PR.
- Title: `type(scope): summary (TASK_ID)`, e.g.
  `feat(framework): problem protocol (FC1)`.
- Description must include:
  - Task ID from `docs/PLAN.md`.
  - Files changed (auto-generated by GitHub is fine).
  - Acceptance criteria from the plan.
  - Exact commands run locally: `pytest`, `ruff check`, `mypy`.
  - Any deviations from the task, with reasoning.
- CI must be green before merge.
- The user merges. The agent does not merge its own PRs.

## Commit hygiene

- Commit messages: `type(scope): summary`, imperative mood.
- Squash merge into `main` so history is one commit per task.
- Never force-push `main`.

## CI

- `.github/workflows/framework.yml` — ruff, mypy, pytest on `framework/python/**`.
- `.github/workflows/water-quality.yml` — pytest on
  `problems/water_quality/**` with framework installed.
- `.github/workflows/frontend.yml` — build + type-check + tests on
  `framework/frontend/**`.
- `.github/workflows/worker-image.yml` — build + push to GHCR on `main`.

Watch CI in the GitHub mobile app. A PR with red CI does not merge, even if
the agent reports local green.

## When the agent is wrong

Comment on the PR with the specific violation and the rule it breaks:

> `qopt/core/problem.py:42` imports `water_quality`. Framework must not import
> plugins (`AGENTS.md`, "Framework rules"). Redo and force-push to this branch.

The agent amends on the same branch. Do not open a second PR.

## When to hand off a task

- A new task = a new ChatGPT conversation. Do not chain tasks in one thread;
  context pollution causes regressions.
- The first message of a new conversation should reference:
  - The repo (`@github YOUR_USERNAME/quantum-opt-dashboard` if using the
    GitHub connector, or the Codex cloud environment).
  - `docs/SESSION_STATE.md`.
  - The task ID from `docs/PLAN.md`.
  - Deliverables and acceptance criteria.
  - The branch name.
- The agent reads the specific files it needs. Do not pre-load files unless
  the task genuinely spans the whole repo.

## What NOT to do

- Do not push directly to `main`.
- Do not merge a PR with red CI.
- Do not accept a PR that skips updating `docs/SESSION_STATE.md`.
- Do not accept a PR that adds `plt.show()`, hardcodes a cache key, or
  imports a plugin from the framework.
- Do not let the agent chain multiple tasks in one PR.
- Do not attach repomix or full-repo dumps when the agent has GitHub access.

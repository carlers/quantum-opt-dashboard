## Release evidence checks: now tested in the *routed unified app*

New `prototypes/unified_dashboard/tests/test_water_evidence_journeys.py` actually opens `unified_dashboard/app.py`, not the standalone water app. The end-to-end checks require:

1. Original **local** default shows an unsolved candidate map and no solver ZIP initially; after actual SCIP solve, `optimal`, original [0,1,3,6,7], readable **literal emitted SCIP LP**, mathematically certified original budget/one-hop rows, matching original model/CSV/result SHA and selected master-feature map, with complete ZIP member hash verification and current download.
2. Switch same routed browser session to **all-15-existing fixed global**. Previous local result/ZIP/selected-site map must be discarded; after actual exhaustive solve, global mode declares `optimal_exhaustive` (NOT SCIP), graph with 20 candidates/15 fixed, all-15-fixed source graph fingerprint/status match current compiled model, exact 860 feasible configurations, and **NO fake SCIP LP in the ZIP**. Switching back to local must invalidate global result/download. The original objective score can remain numerically equal because the optimization objective is the same; source-local and global **feasible domains are not**.
3. Two independent `AppTest` instances start separate browser sessions. A local result and downloaded ZIP must not silently appear in another session. The other session may choose global and solve; this cannot mutate the first session's chosen source graph or ZIP. **This is a Streamlit AppTest state regression, not a formal multithreaded, malicious-user, cross-process isolation/penetration test.**

Each actual current archive must have precisely five bounded ZIP entries including `SHA256SUMS.json`, declared member SHA matching exact uncompressed bytes, and the matching active result and model SHA. Input/source model changes already trigger rerender invalidation by `runtime_attestation.check_visible_result` and related standalone hostile-state tests.

## Residual risks and follow-up scope

1. `pages/water.py` and `pages/custom.py` set **thread-local** `_qopt_unified_page` (correctly avoiding global environment flags for Streamlit page config), but they also prepend folders to **process-global `sys.path`** and do not restore them. This is a potential import namespace/cross-page concurrency footgun; harden only after isolating implicit dependencies/import semantics with dedicated process/session tests, rather than blindly removing paths and breaking lazy imports.
2. `@st.cache_data` for the committed source loader and `@st.cache_resource` for read-only coordinate transformer exist. Verify cache invalidation across actual file updates and that no per-user solve/receipt state is globally cached before preview release. Current main scientific pinned source fingerprint and per-run compiled model/ZIP checks mitigate stale displayed scientific results but are not cryptographic multi-tenant isolation.
3. SCIP **30 second** time limit and exhaustive-search **30 second** deadline are **algorithmic limits**, not OS hard resource quotas. Large K near `C(20,10)=184,756` and overlapping sessions can still consume CPU and memory. Require reviewed concurrent-user budget, worker memory limits, cancellation semantics, Cloud quotas and timeout outcome AppTests before calling the deployed app production-ready.
4. The editable synthetic experiment's 1 MB limits and validated math shapes are positive bounds, but upload content and JSON decoding still deserve adversarial archive/CPU, deeply nested and signed-model review before accepting arbitrary public submissions.
5. Streamlit `download_button` bytes are matched via actual session result/archive testing, but no live **browser-level manual download or Streamlit Cloud click-through** has yet been performed on persistent `preview`. GitHub Actions artifact retention is short-lived (~14 days); no institutional archive or external signer.
6. Original-source mathematical verified N20 does not establish *published manuscript* AHP/WorldPop input parity or *real-world* measured antenna/RF/DO, currents, bathymetry/waterbody field suitability. Do not deploy operational placement recommendations.
